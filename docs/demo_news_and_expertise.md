# 英伟达 CEO 交接与专业期权问答演示

建议安排两个 demo，总长约 5 分钟。第一个展示新近事实如何通过本地资料更新、引用和核查；第二个展示专业字段解释及数据不足时的回答边界。新闻时效与专业知识是两个不同维度，单个新闻问题不能证明所有普通模型都不专业。

## 已核实的资料与实现

本次核对日期为 2026 年 11 月 15 日。英伟达 [CEO 过渡公告](https://nvidianews.nvidia.com/news/nvidia-announces-ceo-transition) 发布于 11 月 12 日；配套 [SEC 8-K Item 5.02](https://www.sec.gov/Archives/edgar/data/1045810/000104581026000082/nvda-20261111.htm) 记录董事会于 11 月 11 日接受黄仁勋辞去总裁、CEO 和董事职务，立即生效。日期不同分别对应事件和公告。

两份文件确认 Colette Kress 出任临时 CEO，并继续担任 CFO；Harvey C. Jones 出任董事长。官方新闻稿将 Jones 称为首任董事长。正式 CEO 的搜寻在公告时点仍在进行，不能把这一快照扩展为对任意后来日期的断言。

已经完成以下接入：

- `data/news_evidence.sqlite3` 的 `news_source_snapshots` 表保存两份原始 HTML、提取文本、审阅摘要、日期和 SHA-256；这是独立新闻证据库，不改写用户聊天。
- `data/news_sources/` 保存对应原文文件，`reports/news_demo_import.json` 记录抓取结果。
- `data/knowledge.json` 新增两条双语公司新闻知识，普通聊天已可检索，总条数为 20。SQLite 负责档案保存，现有 JSON 知识库负责聊天检索，二者不是向量数据库。
- 公司角色追问可在同一话题中找回资料，例如“那她还兼任 CFO 吗？”和“正式继任者是谁？”。这是有限规则路由；系统提示与来源编号检查不构成完整事实验证。

## Demo 1 的问题与操作

打开本地工作台 `/workspace`，新建一个没有绑定期权报告的普通会话，选择 DeepSeek。主问题直接复制：

> 截至2026年11月15日，黄仁勋是否已经离任英伟达（NVIDIA）CEO？请区分离任生效日期与公开公告日期，并说明目前由谁担任 CEO。对无法核实的部分请明确说明。

展开回答下方实际引用的来源，核对日期和职务。随后追问：

> 那她还兼任 CFO 吗？正式继任者是谁？

如果要突出两份文件的对齐，再问：

> 公告日期为什么和生效日期不同？Harvey Jones 与 Colette Kress 分别是什么职务？

第二个独立对照问题用于检查角色混淆：

> 截至2026年11月15日，英伟达（NVIDIA）的 Colette Kress 是临时 CEO 还是正式继任者？她是否继续兼任 CFO，谁担任董事长？请说明信息的依据与日期。

“正式继任者未公布”必须限定于已保存的公告时点。不能凭抓取日期，把 11 月 12 日发布的文件说成 11 月 15 日发布的文件。

## DeepSeek 对照方法与已取得的结果

最清晰的机制对照采用同一个 DeepSeek API 模型，保持问题、系统规则、语言、temperature 0.2、max_tokens 1400、关闭 thinking、空历史一致，仅改变是否提供本地 Reference DATA。题目之间交替 AB/BA 顺序。API 推理仍使用互联网，两边都没有搜索工具；这里的“不联网”应准确说成“关闭联网搜索”。`FINPILOT_OFFLINE=true` 是本地摘录降级，不能用于冒充这一模型对照。

若现场还要展示 DeepSeek 网页版，打开新的网页会话、关闭联网搜索、输入完全相同问题，记录网页显示的实际模型及模式。这是另一次产品对照，不能把 API 结果称为网页版实测。

2026 年 11 月 15 日已实测 `deepseek-flash`，3 题各两组，共 6 次模型请求，完整输出保存在 [首轮原始报告](../reports/news_demo_live_20261115T092220459326Z.json)。本轮结果如下：

| 问题 | 无本地资料 | 接入本地资料 |
| --- | --- | --- |
| 是否离任与日期 | 说明无法核实，未武断确认当前任职 | 区分 11 月 11 日生效、12 日公告，给出临时 CEO 及出处 |
| 临时任职、CFO 与董事长 | 对最新状态保持未知，但附带声称旧背景中黄仁勋也任董事长 | 区分临时 CEO、兼任 CFO 与 Jones 的董事长身份 |
| 能否推出股价或违法结论 | 说明没有原文，并拒绝作这些推断 | 保留事实与结论边界，但有一句把项目解读误写成公告的明确声明 |

无资料组对新闻选择“无法核实”属于合理行为。可展示的具体事实错误是其第二题的董事长背景叙述：官方公告明确称 Jones 是首任董事长。保留完整上下文，不把这次输出描述为“它错误断言黄仁勋现在仍是 CEO”。

RAG 也有措辞局限：第三题的“公告明确不能确立……”应理解为项目对证据范围的判断，原公告并没有作这项声明。不能将有引用等同于每句话都忠实于原文，更不能用这 3 题计算普遍准确率。

针对时点覆盖和来源归属，已修订摘要及通用提示，并保留首轮记录。修订后另跑 6 次请求，见 [第二轮原始报告](../reports/news_demo_live_20261115T092523624948Z.json) 与 [有限语义复核](../reports/news_demo_semantic_review_final.json)。第二轮明确区分项目解读与官方声明，说明 11 月 12 日后人事状态未被快照核实；无资料组仍混写董事和董事长角色。RAG 仍有引用精度残留：第三题“首任董事长”应引新闻稿，回答该条却只引 8-K。该事实有依据，但所贴单条引用不完整。两轮共 12 次请求，全部结果均保留，不据此宣称一般准确率。

## Demo 1 讲稿

“先看一个需要更新知识才能核实的问题。这里不仅要知道谁担任 CEO，还要区分事件生效日、公告发布日，以及临时任职和正式任命。

我们用同一个 DeepSeek 模型做对照。两边都不调用联网搜索，一边没有外部资料，另一边由 FinPilot 提供预先下载到本地的英伟达公告和 SEC 文件。这些资料描述十一月十一日发生、十二日公布的安排；十五日核对文件，并不证明之后没有新任命。

这次无资料组对最新任职选择无法确认，这是合理的。但它在补充背景时说黄仁勋过去也担任董事长；官方公告将 Harvey Jones 称为首任董事长，这一细节有明确出处可以核对。

接入本地资料后，FinPilot 给出了生效日与公告日的区别，也区分了临时 CEO、兼任 CFO 和董事长。请看回答下方的来源，我们可以逐项回到文件检查。这里展示的是本地知识更新与可核查性，仍需要关注回答是否准确表述了原文。”

若改用现场的新回答，按实际情况替换中间一段：

- 对照答错：“这次出现的具体错误是……，对应原文是……。”只指出实际错误。
- 对照拒答：“它没有足够资料，所以保留未知。FinPilot 通过已保存资料进一步回答。”
- 对照答对：“它这次回答正确。继续看两边能否把日期、职务与具体出处对齐。”
- FinPilot 失败：“当前显示实际失败或离线摘录状态，我们查看标明时间的预演记录。”

## Demo 2 的专业问题与操作

使用现成 `/demo`，约 2 分钟。点击“载入真实历史档案”，加载已有 IBKR 历史记录，再点击“检索专家依据”，最后明确点击 AI 解释。这里回放的是 AAPL 2026 年 11 月 6、9、10 日的所收记录，两份期权为 11 月 13 日到期、行权价 350 的看涨和看跌。它们在演示日已经过期，不能当作当前市场信息；载入不重新采集行情。

主问题：

> 这份历史资料来自 IBKR 的 reqHistoricalData，whatToShow 是 TRADES。BarData.volume 能否直接当作当天未平仓量 OI？再取得 OPTION_IMPLIED_VOLATILITY，能否补齐这两份具体期权合约逐日历史 IV 和 Greeks？请区分本次取得的数据、官方接口定义与无法确认的内容，并引用依据。

追问：

> 历史 OI 缺失，能否记成 0 并判断交易者已经平仓？看跌成交更多是否说明多数交易者在看空？

核对四点：成交量不等于未平仓量；本次未取得的 OI 保留缺失；标的层面的历史隐含波动不能冒充具体期权历史 IV/Greeks；成交合约计数不能直接换成独立交易人数或多数人的观点。[OIC 对成交量与 OI 的定义](https://www.optionseducation.org/news/open-interest-why-it-matters) 和 [IBKR 历史条文档](https://www.interactivebrokers.com/docs/tws-api/doc/md/historical-bars) 支持这些专业区分。这里限制的是本次接口和已取得字段，不能泛称所有来源都没有历史 OI。

本次档案时段覆盖未核验完整，不能用不同覆盖的日成交计数强行推导跨日增减。若与另一模型比较推理，须向两边提供同一份样本与缺失说明；否则只能比较资料接入能力。

## Demo 2 讲稿

“刚才考察的是知识能否更新，现在看专业概念是否用对。

这里加载的是已经保存的真实历史资料。成交量有数字，历史 OI 没有返回。缺失并不等于零，成交量也不能当作未平仓量。如果混淆这些字段，就可能编出听起来专业的市场解释。

FinPilot 将这份样本与 IBKR、OIC 等专业资料一起交给模型。我们检查的不只是结论，还包括它能否说明哪些字段已经取得，哪些字段不能互相替代，以及为什么看跌成交较多并不等于多数人在看空。

我们打开对应来源核对。回答应保留样本时间和缺失限制，而不是用缺失数据补出一个确定的行情判断。”

如果观众金融基础较弱，可将第二例换成 `/learn` 的看涨期权试算：行权价 100、每股成本 3.60、乘数 100、1 份、到期价 102。到期现金值 200，初始成本 360，净亏损 160，盈亏平衡 103.60。明确标为合成教学数据，保存试算后追问“为什么涨过行权价仍然亏损？”；讲稿及实际既有两问记录见 [v17 演示脚本](demo_v17.md)。

## 五分钟流程与复现

| 时段 | 屏幕操作 | 演示要点 |
| --- | --- | --- |
| 0:00–0:25 | 并排展示问题与两种条件 | 同一模型，是否提供本地证据 |
| 0:25–1:40 | 新闻主问、角色问、展开引用 | 日期、临时任职、真实错误与拒答分开 |
| 1:40–2:10 | 打开官方原文关键段 | 回到来源核查，而非只看流畅程度 |
| 2:10–2:40 | `/demo` 载入历史档案 | 旧样本、缺失字段、范围 |
| 2:40–4:20 | 检索专家依据并发送两问 | 成交量/OI、历史 IV/Greeks、未知边界 |
| 4:20–5:00 | 展开数据与专家来源 | 每个结论对应哪类证据 |

在项目根目录用 PowerShell 执行：

```powershell
# 已完成一次导入；需要重新下载这两份固定资料时才运行。
.\.venv\Scripts\python.exe scripts\import_news_demo.py

# 零模型请求的预检。
.\.venv\Scripts\python.exe scripts\run_news_demo.py

# 明确发起真实 API 对照，每轮 6 次请求并产生费用。
.\.venv\Scripts\python.exe scripts\run_news_demo.py --live --repeats 1

# 启动新服务进程，读取更新后的知识库。
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

若 8000 已运行，先由演示者正常停止旧服务再启动；也可使用新端口。知识库在进程启动时加载，刷新浏览器不会使旧进程自动读取新增条目。`/api/knowledge` 应列出两条 `nvda-ceo-...` 来源。运行导入脚本只重新下载固定文件，不会自动发现新任命，也不替代新的人工审阅。

预演固定题目，保存所有原始回答与失败，不只挑一次错误。可把已保存报告录屏作为备用，现场标明“预演”及日期。临场模型或网络失败时展示真实模式，不把旧记录或本地摘录当成本次云模型成功。

Python 回归记录见 `reports/tests_news_demo_final.xml`；新增的新闻与对照脚本测试使用受控 provider。新闻真实模型验证为两轮共 12 次 API 请求；第二个 demo 沿用既有专业流程与其验收记录，本轮未重新声称完成其网页或云模型验收。另用独立临时聊天库核对了普通聊天 API 与连续追问，两轮均能找回两条新闻来源；这项 API 检查使用明确标注的离线摘录，不计作云模型成功。
