# v14 演示：历史档案 → 专家依据 → AI 解释

打开已启动的本地服务：<http://127.0.0.1:8000/demo>。约四分钟展示非专业用户如何先认清数据范围，再查看解释依据。完整工作台仍在 <http://127.0.0.1:8000/workspace?view=history>。

**当前验收状态：**受控桌面/移动浏览器流程通过；实际 Edge 中两轮 DeepSeek 问答通过有限数据验收，共四次生成含两次引用修正，零新增 IB 请求。现场仍应按当次模式和提示说明，不把检索排名或历史解释称为预测正确率。

## 一、载入存档，先讲清楚数据是什么

1. 指出页面的三步导航，以及“本页使用独立演示会话”的说明。
2. 点击 **载入真实历史档案**。说明此处读取服务器已经保存的真实 IBKR 历史记录，重新在本地分析；**零次新增 IBKR 采集、零次模型调用**。它会保存新的分析记录，不读取已有聊天。
3. 指出合约身份：AAPL、2026-11-13 到期、350 行权价的看涨/看跌各一份；覆盖纽约交易日期 2026-11-06、09、10。股票数据另作标的参考。
4. 展开来源和限制：数据来自盘中一小时 TRADES bars 的本地汇总，不是官方日终或结算价。各日所收 bar 数不同，完整时段未核验，因此成交计数的跨日变化不可比。
5. 指出 OI 与统计日期缺失，也没有同步双边 BBO 或逐合约历史 IV/Greeks。没有填成零，没有把历史成交末值包装成当前报价。

可这样介绍：“我们先确认这份数据能回答什么。数字来自收到的历史记录，不能因为有一张图，就认为已经知道整个市场现在的想法。”

## 二、检索专业依据，区分候选与引用

点击建议问题或自行输入问题，再明确点击 **检索专家依据**。建议按钮只填入问题，不会自行搜索或调用模型。

推荐问题：

> 看跌成交计数更多，为什么不能直接解释为多数人看空？

展示发布方、原文链接和审阅日期，展开“查看双路检索与选择原因”。说明 BM25 词项排名和中文字符排名通过 RRF 合并；排名分数是匹配启发值，不是正确率。这里展示的是候选资料，模型生成时会针对实际问题重新选取，最终引用在每条回答下方单独列出。

若回答需要某个已识别主题，系统也可能按问题或数据约束补足资料。补足条目会说明原因；没有自然排名时，不能把它说成“BM25 检索第一名”。若没有匹配资料，应直接展示无命中，不声称已找到充分依据。

可这样介绍：“数据卡回答‘样本里观察到什么’，专家来源帮助解释‘这个概念意味着什么、哪些结论不能直接推出’。两种依据不能互相代替。”

## 三、明确选择模型，再解释已保存数据

在 **本次回答引擎** 中选择状态接口标明可用的引擎。只展示真实可用状态；不可用的本地模型不应被介绍为已完成微调并可使用。

编辑问题后点击 **用 AI 解释这批数据**：

> 用白话复盘这几天的期权历史，区分可确认的样本事实与不能比较的部分，并引用对应的专业依据。

这一步才向所选模型发送问题、已保存的历史摘要和选定资料，会产生相应模型请求；不会重新采集行情。等待时展示 Avatar 状态。失败时保留草稿和档案，说明返回的实际模式与限制，不反复点击或把本地回答称为云模型回答。

收到回答后依次展示：

- 本地数值卡及对应历史区间：可核对所收记录，缺失和不可比原因仍在。
- 专家来源卡：实际采用的出处与该段专业主题相符，不是把所有候选链接堆在回答后面。
- 主题检查说明：仅覆盖规则已识别的有限主题，不代表所有语义、因果和措辞都已被证明。

继续追问：

> 这些历史数据能说明现在市场转向看空吗？为什么缺少的持仓不能用当前数补回去？

预期演示重点是保留历史边界、OI 独立日期和样本限制，而不是要求模型给出某个预定涨跌结论。每轮回答保留自己的分析身份、来源与引用；新问题不会改写旧回答。

## 四、展示完整交互体验

切换 2D / 3D，说明显示的是实际 Three.js / SVG Avatar；设备无法使用 3D 时如实显示降级。动作表示处理状态，不是情绪判断置信度；口部动作为程序动画，不宣称音素级唇形同步。

切换中文/英文，使用键盘浏览来源和控件，再开启“减少动态”。在窄屏依次查看来源、专家卡和输入区。现有自动验收覆盖 320、390、1440 视口；这是桌面 Edge 响应式测试，不等于真实手机硬件验收。

模型切换影响后续回答使用的引擎，不改变已经保存的历史数据。若没有可用引擎，档案和本地检索仍然可以演示。重新载入档案会重置本页演示上下文，不读取或改写其他会话。

## 五、说明创新点及真实验证边界

可以用三个具体进步介绍项目：

1. **从字段展示到可比性分析。** 固定合约样本、区分交易时间与导入时间、保留缺失，使普通人看见结论成立的条件。
2. **从附链接到有主题范围的双证据解释。** 14 条审阅知识块标注支持范围；本地数值和专业原则分别引用，错误来源关联可在已识别范围内被检查。
3. **从独立功能到渐进式工作流。** 同一浅色视觉系统连接存档、检索、模型与 Avatar；只有明确操作才进入下一步或请求模型。

也要如实介绍检索局限：开发集 40 例 Recall@4 为 96.88%；算法冻结后的独立 24 例为 87.04%，仍有三条相关问题没有取齐来源、两条无关问题误召回。它们是检索指标，不是金融判断准确率，更不是预测胜率。主题补足和段落检查也不是全能语义蕴含系统。

2026-11-11 的正式演示记录已完成：历史区间 2026-11-06 至 10；实际 DeepSeek 两轮均经一次修正。第一轮价格方向与本地计算一致，成交与 OI 不可比限制保留；第二轮明确不代表当前看空，并将历史 OI 缺失限定在本次历史成交条路径。实际来源按段检查及人工复核通过有限数据验收；首答引用仍出现过错误，失败记录保留，不能宣称所有问题都能正确回答。
