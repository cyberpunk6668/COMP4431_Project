# v15 演示：让鲸鱼娘接着解释同一份金融报告

建议用约五分钟展示 **现成 Q 版 2D 形象、Windows 桌宠、明确共享会话、金融数据与专家来源**。这是课程及个人非商业演示，不宣称官方合作、预测正确率或新的 3D 角色。

受控界面、渲染、跨配置档 SSE 与构建检查已通过，最终服务端 717 项通过。实际 Edge 和打包 Electron 渲染器的两轮 DeepSeek 问答通过，共三次生成含一次受限修正，零新增 IB 请求。Windows 原生报告为 `passed_with_manual_hardware_limits`：九项 instrumentation 通过，但模拟光标/拖动或托盘回调不等于物理硬件认证。

## 1. 准备

1. 确认项目 Python 环境及依赖已安装。运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-desktop.ps1`，桌宠宿主仍依赖本地金融后端。
2. 打开 <http://127.0.0.1:8000/workspace>。本机端口有调整时，使用启动器所示地址。
3. 指出角色来自现成 Q 版鲸鱼娘素材，经过选帧与 WebP 优化，运行图片约 1.09 MiB；不是临时新画的角色，也不是单张图片伪装完整动画。
4. 在“角色来源与非商业许可”中展示 YunYueSama、上善无形、ZipZipPipe 及许可。新角色仅为 2D，旧版机器人仍有原来的 2D/3D 入口。

开场可说：“这次把已经能核查来源的金融助手带到桌面。先明确讨论的是哪份报告，再让模型解释，角色动作只表示处理状态。”

## 2. 展示本地桌宠互动

- 单击角色播放回应，双击或 Enter 打开聊天面板，拖动再放下查看落地动作。
- 将角色移到屏幕左侧再打开面板，面板应选右侧空间，角色仍可直接抓取；右侧则选左边。窄屏预览可收起面板。
- 通过托盘隐藏、显示、恢复位置或修改尺寸；全穿透后仍由托盘恢复。
- 展示“减少动态”和可选休息；安静散步默认关闭。互动、连接和动画不调用模型或 IBKR。

若现场做物理穿透演示，只使用准备好的普通测试窗口作为下层，避免在交易、账户或私人应用上随意点击。当前记录中早期下层按钮零到一的变化没有同步证明宠物 OS 可见，不能介绍为真实穿透验收通过。网页 `/pet` 可以预览角色及聊天，但浏览器预览也不能证明系统置顶、物理拖放和托盘可用。现场未完成的项目应明确说明，不把脚本模拟包装成真实鼠标结果。

## 3. 连接明确选定的会话

1. 在工作台选择用于演示的会话，点击“连接当前会话”。若还没有会话，可从工作台新建。
2. 指出两端显示的连接状态。桌宠只读取这一个 SID；切换到其他网页会话时，桌宠不自动跟随，也不扫描旧聊天。
3. 在桌宠中可发送普通问题，例如“解释一下什么是分散投资”。这是新的现场模型请求，并非本次已记录金融验收题目；按返回的引擎和警告说明真实模式。
4. 回到已连接的工作台，确认保存的问答只有一份。也可以从工作台提问，在桌宠看到相同消息。

共享依赖实际后端 SSE 和数据库，不依赖浏览器与 Electron 共用 localStorage。短暂断线后重新同步已保存内容，不自动重新发问。

## 4. 用历史期权报告展示金融用途

1. 在完整工作台的历史复盘入口，明确点击回放现有真实 IBKR 档案。它读取已存资料，不重新连接网关。
2. 选择“针对这份报告追问”后，确认该会话已连接桌宠；如系统建立了新会话，明确连接这个新会话，不假定桌宠自动跟随。
3. 在桌宠点击“解释本报告”，或输入：

   > 这份历史报告中的未平仓量为什么是缺失？只说明这类历史接口提供哪些字段，以及缺失是否等于零，不讨论走势或下一步操作。

4. 展示真实返回模式、历史区间、本地数值卡和专家来源。已有档案为 AAPL 所选期权样本，期间覆盖不保证完整，OI 与同步双边报价未补造。
5. 在另一端继续追问：

   > 接着解释这批历史样本的看跌成交占比。它能说明现在市场看空吗？只说明这批历史样本的局限，不补充操作建议。

以上是最终实际验证的两道题：工作台首问、桌宠追问。回答保留历史非当前、OI 缺失和看跌占比变化不可比的限制，原档案未变，两端各四条持久化消息且无重复。首问一次生成通过，追问一次生成后经一次修正通过。预期展示的是同一分析的连续解释、时间和来源边界，不是预先安排某种涨跌结论；现场改题不代表已经验证过该新问题。每条旧回复保留当时的分析上下文，新绑定不重写旧回答。

“解释本报告”不会自动刷新行情。需要新的历史资料时，仍由完整工作台明确导入或采集；不要在历史报告上演示伪装实时的一键更新。

## 5. 收尾与验收表达

断开共享后，桌宠清除该会话显示；数据库中的已有会话不因此删除。`/demo` 保持原来的独立演示规则，只共用角色，不自动读入工作台或桌宠聊天。

可介绍的具体进步：

1. **已有角色变成可用的交互入口。** 真实序列动画、原生桌宠控制与网页同款角色结合。
2. **同一份数据跨窗口继续讨论。** 显式连接、持久化后通知、权威重读和旧上下文保留，避免重复消息或旧页面回绑报告。
3. **可爱外观不替代金融依据。** 时间、缺失、不可比、本地数字和专家来源仍可核对，动作不代表判断可信度。

遇到离线、验证失败或网络错误，应展示实际提示和保存的草稿，不反复点击或将本地回答称为云模型成功。真实发送可能包含一次受限引用/格式修正，具体生成次数按验收报告说明。

开发过程曾因未知来源、方向否定和历史接口的同义表述失败，也发现旧机器通过结果漏查了 bars 引用。修复限定在明确主题和否定关系，没有放松未知 ID、资金流或预测保证的拒绝。累计脚本自有六次聊天请求、十一次生成和五次修正全部留档；最终两轮不是“所有问题都首答正确”的证明。

交付收尾已用 `start-desktop.ps1` 启动连接 8000 的可见桌宠；最后的 UIA 检查被用户按 Esc 中断，不计作最终人工验收通过。
