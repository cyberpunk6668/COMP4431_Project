# v13：历史期权复盘、专家知识 RAG 与演示

本轮按用户选择转向历史分析，不要求先购买实时报价。目标是复盘所覆盖日期的样本，并把本地数值依据和有出处的专家解释放在一起。历史数据不能代表此刻行情，也不能独自证明市场情绪或预测方向。

## 数据限制与可用路径

IBKR 官方通常要求历史 bars 具备相应 Level 1 权限。本次实测能返回所选合约，并不能推广为所有历史数据免费或全部实时权限已经开通。[IBKR API FAQ](https://www.interactivebrokers.com/docs/third-party-integrations/general-third-party-frequently-asked-questions)

官方列出已过期期权及期权原生 EOD 数据不可用，因此本项目对未到期合约请求小时成交 bars，再按纽约日期汇总，标为 `derived_from_intraday_trades`，不称为官方日终/结算数据。[历史限制与过滤口径](https://www.interactivebrokers.com/docs/tws-api/doc/md/market-data-limitations)

TRADES bars 表示区间成交 OHLC，BID_ASK bars 的字段含义不同，不能拼成同一时刻可成交双边报价。本项目不从它们制造实时价差。[IBKR bars 字段定义](https://www.interactivebrokers.com/docs/tws-api/doc/md/historical-bars)

工作台提供三个明确区分的入口：

1. **真实网关历史回放**：读取项目中本次真实网关返回的档案，在本地重新分析，不再次请求网关或模型。合约到期后仍可回放既有档案。
2. **历史文件导入**：CSV/JSON，最多 300 行且不超过请求大小限制，来源始终标为用户提供、未独立核验。过期合约可使用合法取得的历史文件，不要求重新从 IBKR 抓取。
3. **教学样例**：服务端生成的合成数据，使用 DEMO 代码并持续显示“非真实行情”。不能伪装成 IBKR 来源。

生产接口 `POST /api/options/history/fetch` 可重新查询未到期的固定合约，参数为 `symbol`、`expiry`、`strike`、`days`（3/4/5 个日历日）。不自动切换合约、扩大范围或购买权限。每次最多请求股票及一对看涨/看跌的三组历史数据，单组二十秒、总体九十秒，和即时采集共享锁。失败只返回安全分类及字段状态，不输出券商原始错误或账号。

## 本地联合分析

`app/options_history.py` 先校验日期、同一到期日、标准乘数、有限数值、非负整数计数、OHLC 关系及重复行。当前纽约交易日和未来日期不作为已结束历史样本。

跨日期的联合比较只使用全期都出现的相同行权价 C/P 配对。少一个合约时不会改变每日分母、补零或补造记录。零成交是已观察到的零；总量为零时，看跌占比无定义。OI 需要独立 `oi_asof_date`；没有统计日期，或首尾仍是同一报告日期时，不产生持仓变化判断。导入资料的交易所日历、发布日期和完整性未由程序独立核验，不能据此宣称无前视偏差的回测。

`evidence` 中的数值和差值由服务器确定性计算；可比性、方向和原因随报告不可变保存。聊天读取这个保存版本，不能让模型自行改写数字。历史卡隐藏实时报价刷新；重新导入或查询建立新报告，旧记录及已有回复保留。

## 专家知识库与具体 RAG

`data/expert_knowledge.json` 是 13 个有出处、带审阅日期的知识块，来源包括 OCC/OIC、Cboe 和 IBKR。涵盖成交与持仓、报告周期、看跌/看涨计数、定价因素、报价价差、历史数据口径及样本限制。“专家知识库”表示有专业出处的整理摘要，不表示专家实时参与回答。

检索由 `app/expert_knowledge.py` 执行：

1. 对查询做词项匹配并运行 BM25 排名；中文术语和英文词项均可命中。
2. 独立计算中文二元、三元字符匹配排名，改善中文表达差异。
3. 用 RRF 合并两个排名，保留词项、主题及双路名次等可解释信息；无相关命中时不硬塞资料。
4. `HistoryChat` 把检索到的知识块、固定历史数据证据及同一分析的对话交给所选模型。
5. 输出经结构、已知引用、数值格式、历史范围和变化方向检查；至多一次同证据格式修正，网络失败不重试，模型阶段总时限六十秒。

这里没有 embeddings、向量数据库或新增微调；也不是复现原 RAG 论文的密集检索训练。研究通过用户指定的 Undermind 核查 RAG、BM25、RRF 论文信息与摘要，通过 GitHub 读取 rank_bm25 实现参考；未修改或发布远程仓库。

- [RAG 原论文](https://doi.org/10.48550/arXiv.2005.11401)
- [BM25 综述](https://doi.org/10.1561/1500000019)
- [RRF 原论文](https://doi.org/10.1145/1571941.1572114)
- [rank_bm25 源码参考](https://github.com/dorianbrown/rank_bm25/blob/master/rank_bm25.py)

模型的本地数值引用使用 `h.*`，专家知识引用使用 `expert.*`，两类证据分别呈现。知识来源不能证明某个导入价格是真的，也不能替代缺失的 OI。每条回答保留历史区间、来源说明、引用及检索排名，导出会话后仍能核查。排名是相关性启发式，不是答案正确率或预测胜率。

首次真实流程在首轮模型校验失败，未发送第二轮；随后用保存的真实分析进行一次无网关诊断重放，确认模型的数量措辞与严格格式规则冲突。现仅将“同一份……合约”这样的身份指代作有限措辞归一，普通数量仍由本地数值卡提供；方向校验也修复了无关免责声明绕过。原失败报告和安全诊断保留在被排除的 `tmp/`，分享版过程见 `reports/history_validation_history_v13.json`，不将离线修剪或旧失败改称真实通过。

人工复核确认最终回答正确区分了逐合约末值变化、成交量不可比、OI 缺失及当前行情边界。但首答有一段将“合约计数不是人数／历史 OHLC 不是同步 BBO”等正确事实附到了主要讲已过期期权和 EOD 限制的知识块上，引用不能完整支持该段。具体备注保存在真实报告的 `manual_review`。当前规则校验引用 ID 和数值，不是逐句来源蕴含证明；因此不能宣传为所有引用完全准确、完整历史期权链或市场预测验证。

移动验收使用桌面 Edge 的响应式视口，不等于真实手机硬件测试。时段覆盖仍未独立核验，历史 OI/IV/Greeks 不完整，旧实时订阅限制也未因历史请求成功而被宣称解决。

服务端不会把 API Key 放入页面或模型输出。模型请求只使用所选历史汇总、检索片段及对应对话；用户导入前应核对文件来源和内容。默认的文件分析与档案回放不调用模型，只有用户发送问题时才调用所选云端或本地引擎。

本轮还只读核对了网关：当前是模拟环境，端口 4002 与项目一致；网关“只读 API”选项未勾选。本项目发送的请求仍只涉及元数据和行情，本轮没有修改该设置、登录环境或订阅。

### 复现

```powershell
.\.venv\Scripts\python.exe -m pytest -q --junitxml=reports/tests_v13.xml
.\.venv\Scripts\python.exe scripts/check_options_history_browser_v13.py
```

以下两个命令只有显式标志才连接实际服务；第一个最多三组历史请求，第二个另外执行两轮模型问答（最多四次生成，含有界格式修正）。它们默认无外部请求。固定 2026-11-13 合约到期后不要重新请求它，应回放档案、导入合法历史数据，或显式选择仍未到期的真实合约。

```powershell
.\.venv\Scripts\python.exe scripts/probe_ibkr_history_v13.py --run --symbol AAPL --expiry 2026-11-13 --strike 350 --days 5
.\.venv\Scripts\python.exe scripts/check_history_live_v13.py --live
```
