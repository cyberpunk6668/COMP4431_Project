# FinPilot v12：真实 IBKR 数据链路排查与修复

本轮针对真实网关的无可用参考价问题进行逐层排查，并验证聊天内刷新、前后比较与连续追问。记录分别区分实时订阅权限、延迟数据可用性、应用的字段处理，以及模型输出校验。

## 根因与证据

| 层次 | 实测事实 | 结论 |
| --- | --- | --- |
| 实时请求 | AAPL 请求模式 1，在观察窗口内收到明确错误 354，没有行情类型或价格回调 | 此标的的这次实时请求未获得订阅支持，不能承诺实时数据 |
| 显式延迟请求 | 请求模式 3，实际回调类型为 3；收到延迟收盘字段 75，买价、卖价和最新成交字段为不可用标记 | 延迟回调确实可达，但可用字段有限，不能说整个接口或全部延迟权限失效 |
| 请求延迟冻结 | 请求模式 4，本次实际仍回调类型 3并返回有限字段 | 请求类型不能替代实际类型，需要以回调为准 |
| 原适配器 | 只接受 bid/ask/last，漏掉普通 close 9 和 delayed close 75；标的观察窗口仅 2.8 秒 | 真实返回的历史参考价被丢弃，而且最初窗口可能在字段到达前结束 |
| 实际到达时间 | 首次延迟诊断在约五秒后收到有效收盘字段 | 修复需覆盖实际异步等待，不能只更改报错文字 |

原始证据采用受限市场消息白名单保存，不含账户、持仓、订单或网关原始错误文本：`reports/ibkr_wire_aapl_1_v12.json`、`reports/ibkr_wire_aapl_3_v12.json`、`reports/ibkr_wire_aapl_4_v12.json`。

IBKR 官方将字段 75 定义为前一日收盘价；它与延迟买价、卖价和最新成交是不同字段。负值或零值与零数量组合还可能表示没有可用行情，不能直接当作有效价格。[IBKR Streaming Data 字段说明](https://www.interactivebrokers.com/docs/tws-api/doc/md/streaming-data)

## 修复

- 独立保存 `close` 和 `close_received_at`，不填入 `bid`、`ask` 或 `last`。
- 标的采样参考按双边中价、最新成交、正收盘参考价的顺序选择；保留当时的 `strike_selection_basis` 和接收时间。
- 标的等待上限改为八秒，收盘字段出现后保留短暂等待，以便升级到更好的成交或双边参考；期权字段观察也为八秒，单次连接总时限为三十秒。离线解码回放覆盖约五秒才返回的收盘参考，以及第七秒后才到达的期权未平仓量、收盘和模型 Greeks 字段。
- 收盘参考只用于选择行权价窗口。依赖价格的分析继续要求有效双边中价和原有配对条件，缺失时不会生成虚假的跨式权利金或波动率比较。
- 识别独立收盘字段为“收到了资料”，但不会把它计入双边报价覆盖。
- 将请求模式、实际模式、权限提示、有效字段与数量、观察时间及回调状态放入安全诊断结构，成功和失败都可以核查。
- 界面明确显示参考价基础、未知的市场交易时刻和独立的本地接收时间。新的分析采集失败时，保留上一次报告并标明它是旧快照。

数据回调类型不等于交易所零延迟保证；冻结和延迟类型有自己的时点含义。[IBKR 行情类型说明](https://www.interactivebrokers.com/docs/tws-api/doc/md/delayed-data)

实际期权样本还出现了部分字段订阅提示 10090。它应与 10167 的延迟回退提示、实际收到的字段一起解释，不能据此宣称全部数据被拒绝，也不能把双边报价缺失唯一归因于休市。

## 如何区分问题

| 诊断事实 | 可以确认 | 不能据此确认 |
| --- | --- | --- |
| 实时请求返回 354 | 本次请求存在明确订阅限制 | 账户的全部标的或所有延迟资料均无权限 |
| 返回 10167 且实际类型为 3、有字段 | 已收到延迟行情，接口回调可达 | 实时订阅已开通，或所有字段都会完整返回 |
| 返回 10090，同时收到持仓或收盘字段 | 部分请求字段受订阅限制，已收到的字段仍可核查 | 全部请求被拒绝；具体应购买哪个产品 |
| 买卖价缺失，但 close/OI/Greeks 到达 | 采集成功但报价证据不足 | 唯一原因是休市，或一定是程序、协议故障 |
| 没有市场回调 | 本次观察没有得到行情 | 单凭超时就认定无权限，或延长等待一定能解决 |

适配器现已处理真实到达的字段；没有修改或绕过 IBKR 的行情权限。当前安装的 `ib_async` 解码路径与市场字段回调已核对，并以真实回调证明链路工作。本地接收间隔只能用于判断应用观察窗口是否过短，不能作为交易所到客户端的端到端延迟测量。

界面的行情选择保留实时、冻结、延迟和延迟冻结。要复现本轮可用链路，在期权分析中显式选择「延迟」并建立报告，再点击「针对这批数据追问」及聊天卡上的「刷新并解释变化」。刷新沿用已保存的标的、到期日、窗口和请求模式；模式 1 的旧报告不会在后台被悄悄降为模式 3。请求模式和实际返回模式同时留档。

## 聊天与模型

新旧快照使用原有不可变存储及本地可比性规则，真实相同值允许显示“未变化”。接收时间更新只证明本次又收到了数据，不证明价格或未平仓量的交易所统计时点已经变化。

模型读取本地汇总和变化证据，正文保持定性，数值由证据卡显示。若结构或引用检查不合格，最多进行一次有界的输出修正，仍使用同一批证据，不重新采集行情，也不在服务连接失败时重复请求。修正仍不合格时保留明确的本地说明。

模型阶段总时限为六十秒。修正只能保留原输出中已有且有效的证据引用；不能增加新的证据引用，方向、数值和不可比规则仍接受同样校验。连续追问中出现的否定句误判已修复：「并不意味着市场看空」可正常解释，但正向因果断言及「不但／不仅」绕过仍拒绝。对快照差异不能凭空指定「采集时点」为主要原因。

可选诊断环境变量 `FINPILOT_OPTIONS_MODEL_DIAGNOSTICS=1` 仅用于本地定位模型校验失败，默认关闭。它只写脱敏后的失败模型输出、校验类型及分析标识到 `tmp/`，不记录请求、提示词或认证头；提交包排除此目录。正常服务未开启该诊断。

页面按钮实际触发第二次网关采集；随后输入市场是否转向的追问，DeepSeek 继续读取新的已保存快照和同一份本地比较。两个答复的全部引用与服务器数据逐项核验；正文没有把持仓样本改变解释成行情方向，也没有把数据接收时间当作行情更新时间。

验证还检查：草稿在刷新期间不丢失，新旧分析标识不同，旧 JSON 与哈希不变，分析历史包含两个版本，导出包含两轮问答及对应快照信息，没有页面异常或横向溢出。验收专用会话已删除，其两个不可变分析留作本地取证，未改动用户其他会话。

人工复核接受这次有限数据解释，但记录两处措辞局限：模型说「成交侧没有有效计数」不够精确，实际上已收到明确的累计量零值，缺失的是零分母下的看跌比例；「报价覆盖恢复」也不能理解为本次建立了过去有报价的基线。结构和引用检查不是完整的语义证明，中文数量词等格式边界仍有盲区；应以本地证据卡和原始字段核查具体数值。

这轮结果证明真实网关刷新、版本保留、有限数据比较和连续问答可用。没有证明完整实时报价可用，也没有验证某个行情订阅产品一定能补齐本次缺失字段。移动端的诊断与刷新布局使用受控接口验收，未单独消耗账户额度重复真实手机采集。

### 剩余实时报价核查

实时模式的 354 需要从当前登录用户、实盘或模拟环境及 API 行情权限核查，程序不能补发缺少授权的价格。IBKR 也说明，在 TWS 可见的实时数据不一定通过 API 可用，因此需要核对 API 下该标的及期权的实际权限，不能只凭界面能看见价格作结论。[IBKR 行情类型与 API 限制](https://www.interactivebrokers.com/docs/tws-api/doc/md/delayed-data)

本轮没有读取账户设置或购买订阅，无法确定需开通哪一项产品，也不能承诺购买某项后必然解决全部缺失字段。完成权限或交易时段核查后，可对同一合约显式请求模式 1 再验证：以实际行情类型、有效双边价格、独立字段时间和覆盖率为准。若仍无回调，再排查连接、请求及网关数据状态；不要把所有失败统一标为「接口故障」。

### 复现

默认不运行真实网关或付费模型；以下显式命令才会触发对应请求：

```powershell
.\.venv\Scripts\python.exe -m pytest -q --junitxml=reports/tests_v12.xml
.\.venv\Scripts\python.exe scripts/diagnose_ibkr_v12.py --run --symbol AAPL --mode 3 --seconds 10
.\.venv\Scripts\python.exe scripts/check_ibkr_refresh_live_v12.py --live --market-data-type 3
.\.venv\Scripts\python.exe scripts/check_ibkr_browser_live_v12.py --live
.\.venv\Scripts\python.exe scripts/package_submission.py
.\.venv\Scripts\python.exe scripts/check_package.py
```

只读请求不访问账户余额、持仓或订单，不发起交易，也不购买行情服务。最终提交包排除密钥、用户数据库和临时模型诊断。
