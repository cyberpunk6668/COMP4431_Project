# FinPilot v10：期权报告与聊天联动

期权分析现在可以直接进入针对当前数据的连续问答。应用保存每次分析的原始报告和本地统计结果，追问通过服务器生成的批次编号读取该快照。每条回复保留自己的批次、时间和证据，即使后来采集了新报告也能回查原来的判断范围。

## 用户操作与功能报告

1. 在期权分析中采集单组或联合报告。
2. 点击「针对这批数据追问」，或选择「这些数据说明什么」「哪项依据最重要」「有哪些不能确定的」「为何不是涨跌预测」。
3. 应用为这份快照开启专属会话，预填问题。用户点击发送后，所选模型才会收到本批汇总摘要。
4. AI 用普通语言解释观察、含义与局限。回复中的依据可展开查看本地数值、标的、到期日、接收时间和行情类型。
5. 可以继续追问，或回看原始报告。移除附加快照后恢复普通聊天，历史回复仍保留原证据。

模型选择适用于下一次发送。DeepSeek 和本地实验模型均沿用所选引擎，本地引擎不可用时明确说明，不会偷偷切换云端。普通知识、写作和编程问题仍可正常回答；明确的财务计算命令继续交给固定公式计算。

## 时间、范围与市场解释

界面标明的是**本地收到这一批数据的时间**，并展示每组自身的时间。这个时间与交易所报价产生时间不是同一个概念。请求的行情类型和 IBKR 实际返回类型也可能不同，因此沿用分析结果中的实际 `market_data_status`，区分实时、冻结、延迟、延迟冻结、混合和不可用。IBKR 通过行情类型回调报告实际类型，订阅权限会影响结果。[IBKR 官方行情类型说明](https://www.interactivebrokers.com/docs/tws-api/doc/md/delayed-data)

快照保存超过 30 秒、时间缺失或异常时，应用不将其作为当前市场状态。30 秒是本地快照年龄提示阈值，不是交易所数据延迟的保证。即使刚刚接收，延迟或冻结行情仍保持原有含义。提问不会自动重新订阅行情；查看此刻市场需要用户重新分析，再选择新报告追问。

回答围绕所选标的、到期日和行权价窗口的已计算汇总指标。多组报告各自保留范围，不直接合并不同标的的合约总数；期限定价只在已有分析确认口径和接收时间可比时解释。失败组保留失败提示，模型不能把未收到的数据补成零。

看跌成交更活跃可以说明当前样本中该类合约交易更多，但不能直接换算为投资者人数或共同看空意图。成交有买卖双方，未平仓量还取决于开仓和平仓，并有自己的更新周期。[OIC 关于未平仓量与买卖双方的说明](https://www.optionseducation.org/referencelibrary/faq/general-information)

当前快照没有新闻或社交媒体来源，因此不据此声称已经测得新闻情绪。回答可以解释风险线索、替代解释和缺少的证据，不输出确定涨跌、获利保证或个别买卖指令。

## 技术实现

| 部分 | 实现与作用 |
| --- | --- |
| 不可变分析记录 | SQLite `option_analyses` 保存服务器计算后的完整报告；每次采集生成新的 UUID，没有客户端覆盖入口 |
| 会话绑定 | `sessions.active_analysis_id` 关联当前批次，切换会话分别恢复，解绑持久化 |
| 消息证据 | `messages.analysis_context` 保存回复当时的范围、时间、行情类型及实际引用证据，导出 JSON 同时保留 |
| 旧库兼容 | 启动时增量添加列，保留现有会话与消息，不清空本地数据库 |
| 模型上下文 | 只从服务器记录挑选已计算的汇总证据、质量元数据和术语解释；不新增账户或交易接口，不发送整张原始合约表 |
| 多轮历史 | 仅携带连续同批次的最近问答，遇到其他批次或普通回复停止继承，限制上下文长度 |
| 输出检查 | 模型返回结构化定性段落及证据编号；检查结构、编号范围、观察引用、数值格式和部分不支持的断言 |
| 本地数值 | 精确数值、单位和时间从原报告读取，不让模型改写或重新计算 |
| 失败降级 | 模型服务失败、未配置或输出未通过验证时，明确显示本地规则说明及警告，保留可用证据 |
| 前端安全 | DOM 文本节点渲染，引用仅定位本条回复的证据；保留键盘操作、焦点状态和减少动态设置 |

主要代码：`app/options_chat.py`、`app/storage.py`、`app/main.py`、`web/app.js`、`web/options.js` 及相应样式。

### API

- `POST /api/options/analyze`：原有单组报告新增 `analysis_id`。
- `POST /api/options/batch`：存在成功组时新增 `analysis_id`；全部失败时为 `null`。
- `GET /api/options/analyses/{analysis_id}`：读取不可变报告，不刷新行情。
- `PUT /api/sessions/{sid}/analysis`：传入 `{"analysis_id":"服务器编号"}` 绑定，传入 `{"analysis_id":null}` 解绑。
- `POST /api/chat`：可传入 `analysis_id` 指定快照；显式 `null` 解绑；省略时继承该会话的服务器绑定。
- `GET /api/sessions/{sid}` 与会话导出：保留当前绑定及每条历史回复的 `analysis_context`。

无效或不存在的批次在调用模型前拒绝。接口只接受分析编号，不接受客户端伪造的报告内容。保存快照和回看都不会自动调用模型。

### 复现

```powershell
.\.venv\Scripts\python.exe -m pytest -q --junitxml=reports/tests_v10.xml
.\.venv\Scripts\python.exe scripts/check_options_chat_browser_v10.py
.\.venv\Scripts\python.exe scripts/check_options_chat_live_v10.py --cloud-fixture
.\.venv\Scripts\python.exe scripts/check_options_chat_live_v10.py --gateway
.\.venv\Scripts\python.exe scripts/package_submission.py
.\.venv\Scripts\python.exe scripts/check_package.py
```

模型验收脚本默认不发起外部请求。`--cloud-fixture` 允许以合成行情进行两次真实 DeepSeek 问答；`--gateway` 允许读取一批真实 AAPL 延迟数据并提问一次。两种模式使用独立临时数据库，报告明确标明来源，不修改用户已有会话。

提交包不包含密钥、本地数据库或运行日志。已保存的分析仅在本地数据库中持久化，不随源码提交包发送。
