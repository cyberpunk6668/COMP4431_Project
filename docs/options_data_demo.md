# 期权数据分析功能：标的波动与风险解读

这个功能读取给定的期权样本，解释期权价格中的波动预期、两翼相对定价和平值期权成本，让一般投资者理解标的风险信息。主线是高层次的风险定价解读，不是买卖信号，也不把局部样本当成整个市场的宏观结论。默认界面不展示逐合约表格或合约可视化；汇总指标和数值依据放在「查看分析依据」中，需要时再展开。

入口为 `/options-demo`，与既有 `/learn` 的盈亏试算和 `/demo` 的历史资料检索分开。页面加载不请求模型；点击「一键分析」或提问时按页面选定的模式运行。配置了可用 DeepSeek 时，可以让真实模型读取样本；没有密钥或选择本地模式时，提供明确标注的本地规则解读。

**数据始终是预设的合成样本，网关行为始终是模拟回放。** AAPL 只是教学标识；报价、成交量、IV、持仓量和日期都不代表真实 AAPL 行情。本页不能证明 IBKR 已连接、账户有实时订阅，或模型正在分析当前市场。真实模型调用与真实市场数据是两回事。

## 推荐流程：两分钟以内英文讲稿（单轮回答）

本版围绕「读取期权数据 → 解释波动与风险定价 → 给出有边界的解读」展开。**只点击一次「一键分析 · DeepSeek」，由系统读取当前样本并生成一次回答；不继续追问，不读取下一批。** 不展示具体合约的表格或图表，也不逐项介绍指标、数值和公式。汇总依据默认收起，来源标识和实际回答模式保持可见。

准备：展开「回答设置」并选择 **DeepSeek**，确认此前已实际跑通模型回答，再点击 **「清空分析」**。以下英文约 **150 词**，讲述配合操作约一分四十秒，预留模型响应时间；等待时继续讲背景与功能流程。实际响应速度需在正式展示前检查。

| --- | --- | --- | --- |
| 0:00–0:25 | 暂时不点击，先介绍开发背景。 | 一般投资者理解期权信息的困难，以及 AI 的作用。 | “Options information can be hard for everyday investors to understand. Prices, volatility, and risk can seem confusing. We built this feature to help people use AI to turn that information into a simple picture of the stock’s risk.” |

讲述时注意：隐含波动率是从期权价格推算的年化定价参数，包含模型假设、风险溢价及供需影响；它不是已实现波动率，也不是确定的未来波动或涨跌方向。没有历史基准，不能仅凭当前水平说“波动率已经偏高”；看跌侧相对 IV 较高也不能单独证明避险需求、恐慌或具体原因。平值跨式中价描述样本中的期权成本，不等于未来必然出现的波动幅度或概率。有限样本无法验证整体经济、全市场宏观状态或新闻因果。

本页的 IV 是直接给定的合成字段，不声称根据这些报价重新拟合了相互一致、无套利的隐含波动率。这里提供的是理解标的风险定价的高层视角，不能称为对真实市场宏观背景的验证。

## 1. 一键启动

在项目根目录双击 **`start-options-demo.cmd`**。脚本使用已有 `.venv`，自动启动独立服务并打开：

<http://127.0.0.1:8018/options-demo>

也可从首页的「期权风险解读 / Options analysis」或「开始期权分析 / Analyze options」，以及工作台的「标的波动与风险解读」进入。它们统一打开 `/options-demo`；「期权互动学习 / Options lab」单独打开 `/learn`，不包含本页的一键分析操作。

然后点击页面上的 **「一键分析」**（云模型模式下显示「一键分析 · DeepSeek」）。页面默认根据模型配置选择引擎；先看引擎与调用提示，再点击。一次操作读取当前样本，解释波动与风险定价，不需要连续提问或现场登录 IB Gateway。指标仍在本地计算，汇总依据按需展开；默认流程不展示逐合约表格或图表。

本机环境未安装时，只需要先按项目 README 完成一次环境安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

之后启动脚本不会重复安装依赖，也不需要 Node.js、实时行情订阅或 `requirements-options.txt`。可选云模型沿用已有 `.env` 的 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` 和 `FINPILOT_OFFLINE`；不要在投屏中打开密钥文件。

需要完全离线、结果固定的彩排时，在项目根目录运行：

```powershell
.\start-options-demo.cmd -Offline
```

`-Offline` 只影响本次独立服务，不会改写 `.env`。若同端口已有另一模式的分析服务，先停止再启动：

```powershell
.\start-options-demo.cmd -Stop
.\start-options-demo.cmd -Offline
```

默认端口 8018 不占用原工作台的 8000。分析服务的数据库和进程记录保存在 `tmp/options-demo/`，日志保存在 `output/options-demo/`。独立进程禁用实际 IBKR 访问，不改变原服务的网关配置，也不读取原有用户会话。重复启动会核对服务身份和本启动器的进程记录后复用；关闭浏览器不会自动停止后端。

## 3. 固定场景和可复核结果（详细依据）

情景：**AAPL 期权：从部分样本到可核查解释**。假设标的价格固定为 100 USD，统一到期日为 2026-11-20，仅选行权价 95、100、105 的 C/P，共六份合约。这个范围不是完整期权链。

| 项目 | 起始批次 | 更新批次 | 可以怎么解释 |
| --- | ---: | ---: | --- |
| 合成教学时间（UTC） | 2026-11-13 15:00 | 2026-11-13 15:02 | 固定回放时点，不是当前接收行情时间 |
| 同一时点的上海时间 | 2026-11-13 23:00 | 2026-11-13 23:02 | 与上行相同的时刻，不是额外数据 |
| 看涨成交量合计 | 800 | 1,000 | 仅为所选样本的合成计数 |
| 看跌成交量合计 | 1,200 | 2,000 | 看跌成交在该样本中更集中 |
| Put/Call 成交量比 | 1.50 | 2.00 | `1,200 ÷ 800` 与 `2,000 ÷ 1,000`，不是看空人数比例 |
| 看涨 / 看跌未平仓量 | 6,000 / 4,800 | 6,000 / 4,800 | 两个批次输入不变；不代表真实 OI 在分钟内实时更新 |
| Put/Call 未平仓量比 | 0.80 | 0.80 | 与成交量比是不同口径 |
| 约 25Δ 看涨 / 看跌 IV | 24% / 32% | 24% / 36% | 来自已给定的合成 IV 与 Delta，不是本页从成交价反推 |
| 约 25Δ 看跌减看涨 IV | 8 个波动率百分点 | 12 个波动率百分点 | 描述相对定价差，不等于下跌概率 |
| 平值跨式中价合计 | 4.80 USD/股 | 5.40 USD/股 | 同行权价两腿中价相加，不是保证可成交的成本 |
| 平值跨式中价 / 标的价 | 4.80% | 5.40% | `4.8 ÷ 100 × 100%`，不是已实现波动率或保证涨跌区间 |
| 有效双边报价覆盖 | 6/6 | 5/6 | 更新批次的 P105 缺少 bid/ask；缺失值保留为空，不填成零 |

两个批次的合约范围固定，因此可比较同口径的计数与相应指标。更新批次保留一处报价缺口，用来说明“收到一些字段”不等于“所有指标都有完整输入”。它不会抹掉已有成交量，也不会让缺失报价自动成为零价格。

页面将固定样本时点与本次处理时间分开显示。今天点击分析，只代表今天重新分析这份预设输入，不会让旧的合成时点变成实时行情。兼容网关结构的 `market_data_type=3` 也只是样本字段；它不能证明 IBKR 真正提供了延迟行情。

## 4. 三分钟中文讲稿（历史详细版本，技术参考）

本节保留早期详细讲法作为技术背景，不作为当前页面的操作稿；其中逐合约表格和具体数值展示不属于当前展示流程。正式讲述使用上方两分钟最终版，必要时只展开「查看分析依据」核对相关汇总值。以下历史时间包含点击、等待与指向证据的停顿，真实模型响应速度不固定。

### 00:00–00:25：先把输入范围讲清楚

**操作：** 打开 `/options-demo`，指向数据来源、样本日期、引擎选择。点击「一键分析」。

> 接下来介绍期权数据分析功能。系统读取选定合约，计算关键指标，再由 chatbot 解释结果。我们选择了一个到期日、三个行权价的六份合约。当前数据来源是页面标注的合成样本，原始输入和分析依据都可以核对。

**按真实模式补一句：**

- 若显示 DeepSeek 成功：“数据虽然是合成的，这次文字解释是所选 DeepSeek 模型实际读取这批输入后生成的。”

### 00:25–01:10：从表格到本地计算

**历史操作参考：** 早期版本展开逐合约表和指标；当前版本只在「查看分析依据」保留相关汇总依据，正式展示不执行此步骤。

> 先看输入：这个教学例子假设标的价格是一百美元。所选样本里，看涨成交量八百，看跌一千二百，所以 Put/Call 成交量比是 一点五。这些数字由程序按样本计算，模型不负责猜一个比例。
>
> 我们还给出了合成的隐含波动率。约二十五 Delta 的看跌 IV 高于看涨八个波动率百分点。平值看涨和看跌的中价相加，是四点八美元，占假设标的价的百分之四点八。它们描述样本中的定价结构，不能直接读成下跌概率或未来一定会到达的价格范围。

### 01:10–01:45：让 chatbot 解释，并检查推理边界

**操作：** 阅读回答，点击预设问题「看跌成交更多，能说明多数人在看空吗？」后点击「发送给 DeepSeek」；需要核对时再展开对应证据。

> chatbot 读取的就是刚才这批样本和计算结果。它应该解释“这个样本中看跌成交更多”，同时指出不能推出“多数投资者看空”。每笔成交都有买卖双方，合计成交量没有告诉我们谁主动买入、谁在对冲，或者是否属于组合交易。
>
> 我们展示的不只是流畅的回答，也展示回答用了哪些数字，以及这些数字不能证明什么。

### 01:45–02:30：读取下一批，查看更新分析

**操作：** 点击「读取下一批」，查看变化卡及新回答。

> 现在读取下一批样本，合约范围保持一致。看跌成交量变成两千，看涨变成一千，比值从一点五升到二。看跌与看涨的 IV 差从八扩大到十二个波动率百分点，平值跨式中价占比从百分之四点八变成百分之五点四。
>
> 这里可以比较前后相同范围的变化。更新批次还缺少一份合约的双边报价。界面保留缺失值，报价覆盖变成六份中的五份，chatbot 会把这个限制一并解释。这些指标只描述给定样本，不能据此建议买卖。

### 02:30–03:00：说明它与真实 IBKR 链路的关系

**操作：** 指向数据来源与真实工作台入口。若时间允许，点击「缺少报价会怎样影响分析？」；根据实际回答说明。

> 这个功能把流程拆成数据输入、本地指标计算和 chatbot 解释。当前页面分析固定的合成样本，项目原有工作台还提供 IBKR 只读采集入口，需要另外检查登录、API 配置、订阅权限和实际返回的数据类型。

> 系统能够读取给定样本、复核计算、解释同范围变化，并暴露缺失数据。分析结果保留来源和适用范围，用户可以带着依据继续追问。

## 6. 实现路径与真实网关的区别

本功能使用独立 API：

```text
GET  /api/options-demo/scenario
     → 情景、预设问题、模型是否配置；不连接网关、不生成模型回答

POST /api/options-demo/run
     {"frame":0或1,"engine":"local"或"deepseek","question":"可选问题"}
     → 固定网关格式样本
     → 项目既有 analyze_option_snapshot 本地计算
     → 指标、变化、缺失字段与证据
     → 本地规则说明，或显式真实模型解释
```

页面分析固定的合成样本，不请求现有行情 API。两个批次时间固定，分析以相应样本时点评估数据，另记本次处理时间。不同问题读取指定批次，不会切换到另一批合约。已有工作台、聊天记录和 IBKR 分析流程保留。

默认启动的独立分析进程把 `IBKR_ENABLED` 设为 `false`，所以要使用真正采集时，应打开**原有、单独运行并已配置 IBKR 的服务**，例如：

<http://127.0.0.1:8000/workspace?view=options>

真实采集的设置与已有验收边界见 [IBKR 网关技术说明](ibkr_gateway_v12.md)。现有文档报告过延迟资料及双边报价缺失，不能拿本页合成的完整报价来覆盖真实采集限制。本功能此次未完成新的真实网关验收。

## 7. 常用命令和故障处理

```powershell
# 只启动，供测试或稍后手动打开浏览器
.\start-options-demo.cmd -NoBrowser

# 端口被其他服务占用时，另开独立端口
.\start-options-demo.cmd -Port 8019

# 停止该启动器持有的分析进程；不会按端口随意杀进程
.\start-options-demo.cmd -Port 8019 -Stop

# 使用指定 Python 环境
.\start-options-demo.cmd -Python "C:\path with spaces\python.exe"
```

- **提示缺少 Python 或依赖：** 按 README 安装一次环境，再运行启动器。启动器不替换现有环境。
- **提示端口被占用：** 用 `-Port 8019`。即使占用者也是另一份 FinPilot，本启动器也不会接管身份不匹配的进程。
- **修改代码或 `.env` 后没有生效：** 先使用同端口 `-Stop`，再启动。脚本不使用自动重载。
- **模型未配置或离线：** 使用本地模式，或在投屏前私下检查 `.env`；修改后重启独立服务。`-Offline` 会明确禁用云调用。
- **模型超时或校验失败：** 依页面显示说明这是降级。本地指标仍可核查；不要把降级文字宣称为真实模型生成成功。
- **窗口关闭后仍占用端口：** 浏览器关闭不会退出服务。使用同端口 `-Stop` 关闭本启动器创建的后端。
- **启动失败：** 查看控制台错误及 `output/options-demo/` 最近的 `.stderr.log`，日志不应包含密钥；不要直接展示或上传 `.env`。
