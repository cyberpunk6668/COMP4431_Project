# 期权数据分析 Demo：部分样本 → 本地计算 → Chatbot 解释

这个演示回答一个具体问题：**chatbot 能否读取给定的期权样本，用可复核的数字解释成交结构、相对定价与数据缺口，并在下一批数据到来后更新解释？**

入口为 `/options-demo`，与既有 `/learn` 的盈亏试算和 `/demo` 的历史资料检索分开。页面加载不请求模型；点击演示或提问时按页面选定的模式运行。配置了可用 DeepSeek 时，可以让真实模型读取样本；没有密钥或选择本地模式时，展示明确标注的本地规则解读。

**数据始终是预设的合成样本，网关行为始终是模拟回放。** AAPL 只是教学标识；报价、成交量、IV、持仓量和日期都不代表真实 AAPL 行情。本页不能证明 IBKR 已连接、账户有实时订阅，或模型正在分析当前市场。真实模型调用与真实市场数据是两回事。

## 1. 一键启动

在项目根目录双击 **`start-options-demo.cmd`**。脚本使用已有 `.venv`，自动启动独立服务并打开：

<http://127.0.0.1:8018/options-demo>

然后点击页面上的 **「一键演示」**。页面默认根据模型配置选择引擎；先看引擎与调用提示，再点击。一次操作依次呈现部分期权数据、计算指标与对应解释，无需现场登录 IB Gateway。

本机环境未安装时，只需要先按项目 README 完成一次环境安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

之后启动脚本不会重复安装依赖，也不需要 Node.js、实时行情订阅或 `requirements-options.txt`。可选云模型沿用已有 `.env` 的 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` 和 `FINPILOT_OFFLINE`；不要在投屏中打开密钥文件。

需要完全离线、结果固定的彩排时，在项目根目录运行：

```powershell
.\start-options-demo.cmd -Offline
```

`-Offline` 只影响本次独立服务，不会改写 `.env`。若同端口已有另一模式的演示服务，先停止再启动：

```powershell
.\start-options-demo.cmd -Stop
.\start-options-demo.cmd -Offline
```

默认端口 8018 不占用原工作台的 8000。演示数据库和进程记录保存在 `tmp/options-demo/`，日志保存在 `output/options-demo/`。独立进程禁用实际 IBKR 访问，不改变原服务的网关配置，也不读取原有用户会话。重复启动会核对演示身份和本启动器的进程记录后复用；关闭浏览器不会自动停止后端。

## 2. 展示前的准备

1. 启动页面，确认顶部标记为合成数据、模拟网关回放，真实网关未连接。
2. 选择本次要讲的模式：真实 DeepSeek 展示真实模型读取样本；本地规则模式用于稳定彩排。两者都使用同一份合成输入。
3. 先完整试走一次「一键演示 → 播放下一帧 → 预设问题」。正式开始前点击「重新开始」，清空当前展示；此操作重置页面，不改数据文件。
4. 需要真实模型时，提前核验页面实际显示模型成功。超时、配置缺失或输出校验失败后的本地说明，只能称为本地降级结果。模型请求可能产生费用；不要把尚未执行的请求当作已成功。

推荐投屏使用桌面浏览器，放大到观众能读清样本表和回答。数据来源标识应保持可见，不用“已连接”“实时刷新”等词替代“回放”。

## 3. 固定场景和可复核结果

情景：**AAPL 期权：从部分样本到可核查解释**。假设标的价格固定为 100 USD，统一到期日为 2026-11-20，仅选行权价 95、100、105 的 C/P，共六份合约。这个范围不是完整期权链。

| 项目 | 第 1 帧 | 第 2 帧 | 可以怎么解释 |
| --- | ---: | ---: | --- |
| 合成教学时间（UTC） | 2026-11-13 15:00 | 2026-11-13 15:02 | 固定回放时点，不是当前接收行情时间 |
| 同一时点的上海时间 | 2026-11-13 23:00 | 2026-11-13 23:02 | 与上行相同的时刻，不是额外数据 |
| 看涨成交量合计 | 800 | 1,000 | 仅为所选样本的合成计数 |
| 看跌成交量合计 | 1,200 | 2,000 | 看跌成交在该样本中更集中 |
| Put/Call 成交量比 | 1.50 | 2.00 | `1,200 ÷ 800` 与 `2,000 ÷ 1,000`，不是看空人数比例 |
| 看涨 / 看跌未平仓量 | 6,000 / 4,800 | 6,000 / 4,800 | 两帧输入不变；不代表真实 OI 在分钟内实时更新 |
| Put/Call 未平仓量比 | 0.80 | 0.80 | 与成交量比是不同口径 |
| 约 25Δ 看涨 / 看跌 IV | 24% / 32% | 24% / 36% | 来自已给定的合成 IV 与 Delta，不是本页从成交价反推 |
| 约 25Δ 看跌减看涨 IV | 8 个波动率百分点 | 12 个波动率百分点 | 描述相对定价差，不等于下跌概率 |
| 平值跨式中价合计 | 4.80 USD/股 | 5.40 USD/股 | 同行权价两腿中价相加，不是保证可成交的成本 |
| 平值跨式中价 / 标的价 | 4.80% | 5.40% | `4.8 ÷ 100 × 100%`，不是已实现波动率或保证涨跌区间 |
| 有效双边报价覆盖 | 6/6 | 5/6 | 第 2 帧的 P105 缺少 bid/ask；缺失值保留为空，不填成零 |

两帧的合约范围固定，因此可比较同口径的计数与相应指标。第 2 帧故意保留一处报价缺口，用来说明“收到一些字段”不等于“所有指标都有完整输入”。它不会抹掉已有成交量，也不会让缺失报价自动成为零价格。

页面将固定教学时间与本次处理时间分开显示。今天点击播放，只代表今天重新分析这份预设输入，不会让旧的合成时点变成实时行情。兼容网关结构的 `market_data_type=3` 也只是样本字段；它不能证明 IBKR 真正提供了延迟行情。

## 4. 三分钟中文讲稿

以下时间包含点击、等待与指向证据的停顿。真实模型响应速度不固定；遇到等待就展示输入范围和数值依据，避免承诺固定响应秒数。

### 00:00–00:25：先把输入范围讲清楚

**操作：** 打开 `/options-demo`，指向合成来源标识、固定日期、引擎选择。点击「一键演示」。

> 这次展示的是我们的 chatbot 如何读取一部分期权数据，再给出能回到原始数字核对的解释。这里使用模拟网关回放：数据不是实时行情，也没有连接 IBKR。我们固定选择一个到期日、三个行权价的六份合约，让演示能稳定复现。

**按真实模式补一句：**

- 若显示 DeepSeek 成功：“数据虽然是合成的，这次文字解释是所选 DeepSeek 模型实际读取这批输入后生成的。”
- 若显示本地规则：“这次先用本地规则展示固定结果；它没有调用云模型。真实模型读取同一样本的入口也保留在页面上。”
- 若发生降级：“这次模型调用没有成功，我们保留明确标注的本地说明，不能把它算作模型成功。”

### 00:25–01:10：从表格到本地计算

**操作：** 指向样本表，再指向 Put/Call、IV 差、跨式权利金指标及依据。

> 先看输入：这个教学例子假设标的价格是一百美元。所选样本里，看涨成交量八百，看跌一千二百，所以 Put/Call 成交量比是 一点五。这些数字由程序按样本计算，模型不负责猜一个比例。
>
> 我们还给出了合成的隐含波动率。约二十五 Delta 的看跌 IV 高于看涨八个波动率百分点。平值看涨和看跌的中价相加，是四点八美元，占假设标的价的百分之四点八。它们描述样本中的定价结构，不能直接读成下跌概率或未来一定会到达的价格范围。

### 01:10–01:45：让 chatbot 解释，并检查推理边界

**操作：** 阅读回答，点击预设问题「看跌成交更多，能说明多数人在看空吗？」；指向对应证据。

> chatbot 读取的就是刚才这批样本和计算结果。它应该解释“这个样本中看跌成交更多”，同时指出不能推出“多数投资者看空”。每笔成交都有买卖双方，合计成交量没有告诉我们谁主动买入、谁在对冲，或者是否属于组合交易。
>
> 我们展示的不只是流畅的回答，也展示回答用了哪些数字，以及这些数字不能证明什么。

### 01:45–02:30：播放第二帧，展示更新分析

**操作：** 点击「播放下一帧」，查看变化卡及新回答。

> 现在回放第二批预设数据，合约范围保持一致。看跌成交量变成两千，看涨变成一千，比值从一点五升到二。看跌与看涨的 IV 差从八扩大到十二个波动率百分点，平值跨式中价占比从百分之四点八变成百分之五点四。
>
> 这里可以比较前后相同范围的变化。但这些只是我们设置的情景变化，不是当前市场正在变化，也不能据此建议买卖。第二批还故意缺少一份合约的双边报价。界面保留缺失值，报价覆盖变成六份中的五份，chatbot 需要把这个限制一并讲出来。

### 02:30–03:00：说明它与真实 IBKR 链路的关系

**操作：** 指向数据来源与真实工作台入口。若时间允许，点击「缺少报价会怎样影响分析？」；根据实际回答说明。

> 这个演示把流程拆成数据输入、本地指标计算和 chatbot 解释。为了课堂稳定，我们把数据输入换成固定回放。项目原有工作台仍有真正的 IBKR 只读采集入口，但需要另外检查登录、API 配置、订阅权限和实际返回的数据类型。
>
> 今天演示证明的是：系统能读取这份给定样本、复核计算、解释同范围变化，并暴露缺失数据。它不证明实时 IBKR 已连通，也不证明模型能预测市场。

## 6. 实现路径与真实网关的区别

本演示使用独立 API：

```text
GET  /api/options-demo/scenario
     → 情景、预设问题、模型是否配置；不连接网关、不生成模型回答

POST /api/options-demo/run
     {"frame":0或1,"engine":"local"或"deepseek","question":"可选问题"}
     → 固定网关格式样本
     → 项目既有 analyze_option_snapshot 本地计算
     → 指标、变化、缺失字段与证据
     → 本地规则说明，或显式真实模型解释
```

页面不会通过现有行情 API 假装采集。两帧时间固定，分析以相应教学时点评估样本，另记本次处理时间。不同问题读取指定帧，不会偷偷切换到另一批合约。已有工作台、聊天记录和 IBKR 分析流程保留。

默认启动的独立演示进程把 `IBKR_ENABLED` 设为 `false`，所以要展示真正采集时，应打开**原有、单独运行并已配置 IBKR 的服务**，例如：

<http://127.0.0.1:8000/workspace?view=options>

真实采集的设置与已有验收边界见 [IBKR 网关技术说明](ibkr_gateway_v12.md)。现有文档报告过延迟资料及双边报价缺失，不能拿本页合成的完整报价来覆盖真实采集限制。本次 demo 本身没有完成新的真实网关验收。

## 7. 常用命令和故障处理

```powershell
# 只启动，供测试或稍后手动打开浏览器
.\start-options-demo.cmd -NoBrowser

# 端口被其他服务占用时，另开独立端口
.\start-options-demo.cmd -Port 8019

# 停止该启动器持有的演示进程；不会按端口随意杀进程
.\start-options-demo.cmd -Port 8019 -Stop

# 使用指定 Python 环境
.\start-options-demo.cmd -Python "C:\path with spaces\python.exe"
```

- **提示缺少 Python 或依赖：** 按 README 安装一次环境，再运行启动器。启动器不替换现有环境。
- **提示端口被占用：** 用 `-Port 8019`。即使占用者也是另一份 FinPilot，本启动器也不会接管身份不匹配的进程。
- **修改代码或 `.env` 后没有生效：** 先使用同端口 `-Stop`，再启动。脚本不使用自动重载。
- **模型未配置或离线：** 使用本地模式，或在投屏前私下检查 `.env`；修改后重启独立服务。`-Offline` 会明确禁用云调用。
- **模型超时或校验失败：** 依页面显示说明这是降级。本地指标仍可核查；不要把降级文字宣称为真实模型生成成功。
- **窗口关闭后仍占用端口：** 浏览器关闭不会退出服务。使用同端口 `-Stop` 关闭本启动器创建的后端。
- **启动失败：** 查看控制台错误及 `output/options-demo/` 最近的 `.stderr.log`，日志不应包含密钥；不要直接展示或上传 `.env`。
