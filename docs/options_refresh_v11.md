# FinPilot v11：聊天内刷新与前后变化解释

本次在已有期权追问会话中加入显式刷新。用户无需返回分析页，一次点击即可重新采集当前范围、保存新版本，并让所选模型解释前后差异。历史报告、原数值和既有回复保持各自的时间与依据。

## 使用方式与功能

1. 先将单组或联合期权分析附加到聊天。
2. 点击快照卡上的「刷新并解释变化」。按钮附近说明会重新采集相同范围，并把新旧汇总发送给当前模型；没有额外确认框。
3. 采集与解释期间，界面锁定重复刷新、模型切换和会话切换，输入框已有草稿保留，不自动发送草稿。
4. 有成功数据时生成新的分析编号，聊天追加刷新意图与解释，后续追问使用新结果。
5. 展开「分析记录」可回看旧版本。回看只读取保存的报告，不重新采集，也不会切换当前批次。

采集失败时，当前绑定、旧报告和消息保持不变。采集成功但模型不可用或回答未通过校验时，新数据仍会保存并附加，界面明确展示本地变化说明和服务提示。

## 前后变化的口径

| 检查 | 比较规则 |
| --- | --- |
| 标的与到期日 | 按同一标的、到期日配对，不依赖批次中的排列顺序；已成功解析的日期固定，不因过期自动换成另一天 |
| 合约定义 | 核对交易类别、币种和乘数，缺失或变化时不生成可比差值 |
| 抽样窗口 | 请求的行权价集合必须一致，防止移动的取样窗口被当作市场变化 |
| 行情类型 | 按实际收到的类型核对，实时、冻结、延迟及延迟冻结之间的变化不能直接相减 |
| 接收时间 | 新时间必须晚于旧时间，并保留双方带时区的本地接收时间；缺失或异常时不声称可比 |
| 成交与未平仓 | 核对字段实际配对的行权价集合；成交还核对纽约接收日期，跨日不比较日累计差值 |
| 报价覆盖 | 核对请求的合约分母；覆盖变化说明资料完整程度变化，不能当作价格方向 |
| 买卖价差 | 核对指标实际使用的有效报价合约集合，防止不同合约子集的中位数被误比 |
| 隐含波动率 | 核对近平值行权价与计算口径，才能比较对应的波动定价指标 |
| 缺失与部分失败 | 保留前后可用值、失败范围和不可比原因，缺失不填零，不生成伪差值 |

本地计算的变化采用「新值减旧值」。比例的差值显示为百分点，例如六成到七成对应增加十个百分点；不会把它误写成增加百分之十。隐含波动率的差值显示为波动率点，合约总数的差值保持合约单位。

这里只能比较收到的快照字段。成交累计计数差不等于精确的区间新增成交；本地纽约日期不能证明交易所统计周期完全一致。未平仓量还有独立的清算更新周期，其变化不能当作资金流入或新增方向性仓位。[OIC 关于未平仓量统计周期的说明](https://www.optionseducation.org/referencelibrary/faq/general-information)

重新采集不代表获得实时行情权限。界面继续标注 IBKR 实际行情类型与本地接收时间，延迟或冻结数据仍按其本来含义解释。[IBKR 官方行情类型说明](https://www.interactivebrokers.com/docs/tws-api/doc/md/delayed-data)

## 技术实现

`app/options_refresh.py` 保存并恢复服务器生成的采集参数，强制关闭采集阶段的额外模型解读，待新数据保存后再进行一次聊天解释。新报告保留原始半径、请求行情类型和固定的成功到期日；早期报告可以根据已有快照信息恢复受限参数，无法安全重建时明确报错。

`app/options_changes.py` 根据已保存的两份报告核对可比条件，计算有限且可核验的差值，输出 `refresh_comparison`。每组包含前后时间、行情类型、指标的前值、后值、差值和不可比原因。模型读取这些本地结果，只生成定性解释，不重新计算数值。证据卡中的变化量直接取自保存记录。

SQLite 的 `session_analysis_history` 保存会话的分析版本。刷新提交在同一数据库事务中核对原绑定、插入新快照、切换当前批次并记录历史；若绑定已变化则拒绝提交。旧报告和消息不做覆盖。历史引用受到删除保护，解除当前绑定不会抹除分析记录。

同一会话同时只允许一个刷新请求。服务端额外校验客户端提供的期望批次，过期的重复请求不会再次采集；刷新接口按共享路径限流，不能通过更换会话编号绕过限制。前端的忙碌状态和会话序号也阻止重复点击与过期响应覆盖。

### 接口

`POST /api/sessions/{sid}/analysis/refresh` 请求：

```json
{"analysis_id":"当前服务器分析编号","language":"zh","engine":"deepseek"}
```

请求只指定期望批次、语言和模型，不接受客户端替换采集参数或报告内容。响应包含 `user_message`、`answer`、`mode`、`analysis_context`、`active_analysis` 和 `analysis_history`。新报告通过 `previous_analysis_id` 指向前一份，`refresh_comparison` 保留比较结果。

`GET /api/sessions/{sid}`、聊天响应与会话导出增加轻量的 `analysis_history`，按最近附加顺序排列，标出当前版本。`GET /api/options/analyses/{analysis_id}` 继续提供不可变报告的只读回看。

真实网关的原始失败报告保留了当时接口返回的 `ibkr_entitlement_missing`。进一步诊断仅捕获 `10167` 延迟回退提示及信息码，不能证明延迟行情权限也被拒绝。已修正传输层分类：明确请求延迟／延迟冻结时，只有此提示且没有有效报价，返回数据不可用；明确的权限拒绝仍分别处理。该修复由六项专门测试验证，没有把旧报告改写成新逻辑实测，也没有自动更换用户请求的行情类型。

浏览器验收使用受控响应；真实模型验收使用合成市场数据及隔离数据库中的 FastAPI 接口。移动视口属于桌面 Edge 仿真。当前网关的数据可用性仍限制真实刷新验证，系统不会为填补结果而制造数值。

### 复现命令

```powershell
.\.venv\Scripts\python.exe -m pytest -q --junitxml=reports/tests_v11.xml
.\.venv\Scripts\python.exe scripts/check_options_refresh_browser_v11.py
.\.venv\Scripts\python.exe scripts/check_options_refresh_live_v11.py --cloud-fixture
.\.venv\Scripts\python.exe scripts/check_options_refresh_live_v11.py --gateway
.\.venv\Scripts\python.exe scripts/package_submission.py
.\.venv\Scripts\python.exe scripts/check_package.py
```

模型脚本默认不发起外部调用；显式的验收参数才会触发相应请求。提交包排除密钥、本地数据库、运行日志与临时诊断文件。真实行情权限、模型语言准确性与真实手机硬件表现分别有各自的限制，界面或引用校验不构成投资预测准确率保证。
