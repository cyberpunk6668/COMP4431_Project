## 1. 项目目标与边界

FinPilot 面向希望理解基础金融概念、比较一般金融产品风险、进行简单财务情景计算的用户。系统使用 DeepSeek 提供自然语言组织能力，以本地人工整理的金融知识库提供可追溯依据，并通过确定性计算器处理金额和利率运算。

本项目选择的基础功能是中英双语金融问答。附加功能包括知识检索与来源展示、结构化财务计算、会话持久化与导出、可交互界面，以及依浏览器能力启用的语音输入与朗读。v2 增加原创 2D/3D 形象、明暗主题及本地 Qwen3-0.6B LoRA 实验流程。知识检索仍采用本地词法方法，没有部署向量数据库。云端 DeepSeek 权重未修改；本地 LoRA 的训练事实与效果应以实际清单和对照报告核验。

系统用于金融教育与课程演示。在 v2 历史基线中，当时没有接入实时行情或账户网关，也不提供订单执行或收益预测服务；v12 的只读网关接入与行情限制以上方现状说明及专项文档为准。用户输入的假设利率不代表预期回报；任何计算结果都不应被表述为投资承诺。涉及存款保障、税务和监管的知识必须保留适用地区，不将美国或香港制度直接套用于其他地区。

## 3. 系统结构

浏览器前端通过同源 HTTP 接口访问 FastAPI。后端负责输入验证、请求路由、检索、计算、会话存储，以及调用 DeepSeek。浏览器不会直接连接 DeepSeek，API Key 仅在服务端配置中使用。

```text
Browser UI + Three.js / SVG avatar
  | same-origin HTTP / JSON
FastAPI application
  |-- request validation / domain routing
  |-- deterministic calculators
  |-- local knowledge retrieval
  |-- DeepSeek provider client
  |-- optional local LoRA subprocess (cached base + adapter)
  |-- explicitly labelled offline response
  `-- SQLite sessions and messages

External boundary: DeepSeek receives the selected prompt context.
Local boundary: knowledge JSON, configuration and SQLite stay on host.
```

前端采用原生 HTML、CSS 与 JavaScript，不依赖外部 CDN。这样可减少课堂演示时对互联网前端资源的依赖；联网生成仍依赖 DeepSeek 服务。界面输出使用安全的文本节点，不把模型输出当作可信 HTML 执行。

## 4. 一次问答的数据流

1. 用户在界面选择语言并提交问题，前端发送消息与会话标识。
2. 服务端校验字段、长度与数值范围，确认会话存在或建立新会话。
3. 可确定执行的计算意图进入计算路径；普通知识问题进入检索路径。
4. 检索器从固定知识库中选出相关条目，并向生成模型提供有限的知识上下文。
5. 已配置且请求成功时，由 DeepSeek 组织答案；未配置或请求失败时，使用标明原因的本地知识回答。
6. 系统将用户与助手消息写入 SQLite，返回答案、来源和实际执行模式。
7. 前端显示回答、引用链接、模式状态与可用的会话操作。

`deepseek` 表示本次回答成功调用模型，`offline` 表示本地回答，`calculator` 表示确定性计算路径，`local-lora` 表示成功使用本地适配器生成。配置了密钥只说明具备尝试调用的条件，不证明网络、余额、模型权限或服务可用。

## 5. 知识库与检索

知识库保存条目标识、标题、分类、来源 URL、整理日期、内容与检索关键词。来源优先采用监管机构、投资者教育机构和官方 API 文档。条目是教育性摘要，不是实时抓取或自动同步的新闻流。

检索采用 BM25 词法相关性与中英关键词匹配，返回数量有限的候选来源。当前知识库包含 18 个条目。文本先作 NFKC 规范化与小写转换，英文使用停用词和简单词尾处理，中文使用连续双字切分，不需要下载分词模型。

BM25 使用 k1=1.2、b=0.75，根据词频、逆文档频率和文档长度计算分数，再加入显式主题关键词的匹配增益。英文别名采用词边界，避免将 apricots 中的 apr 错当利率术语。候选条目必须命中自身的主题词，最多返回 3 条，不为凑足引用数量而附加无关来源。这个门槛有助于拒绝领域外问题，但也会拒绝没有命中词表的真实金融问题。排名分数不是概率或经校准的置信度。

相比大型向量检索系统，这种方案部署依赖少、来源清楚、便于课堂复现，但对未收录概念、口语改写、错别字、长距离语义关联的覆盖有限。

评估脚本使用固定测试集记录期望来源，并计算 Recall@3 与 MRR。Recall@3 衡量预期相关来源是否进入前三项；MRR 根据首个相关结果的排名计分。该评估衡量的是知识检索，不能替代对模型答案真实性、完整性和金融适用性的人工审阅。评估集由开发过程整理，与知识库存在同源偏差，不代表开放世界问答准确率。

来源卡片表示系统检索并提供了相应资料，并不自动证明答案每一句都被资料支持。模型可能误读、遗漏限定条件或生成错误陈述；用户应打开来源核实重要信息。

## 6. 确定性财务计算

计算器使用十进制运算，向前端返回公式、假设、结果与用于绘图的序列。计算与语言模型解耦，模型不承担金额计算职责。展示值按货币精度舍入，内部计算保留更高精度。

### 6.1 复利与定期投入

设初始本金为 P、名义年利率为 r、每月投入为 C、总月数为 n，月利率 i = r / 12。这里 r 为小数，界面输入的 5 表示 5%，不是 500%。投入假设发生在月末。

```text
FV = P * (1 + i)^n + C * ((1 + i)^n - 1) / i
if i = 0: FV = P + C * n
```

系统将名义年利率按月折算。它不是年化收益率 APY 的反推，也未自动计入税费、管理费、通胀、波动和汇率变化。固定利率示例只用于比较假设情景。

### 6.2 等额本息贷款

设贷款本金为 P、月利率为 i、总期数为 n，则月还款额为：

```text
A = P * i / (1 - (1 + i)^(-n))
if i = 0: A = P / n
total_paid = A * n
interest = total_paid - P
```

假设利率固定、每月支付、无手续费、无提前还款。最终一期可能因展示舍入与银行实际还款表存在细微差异。该工具不是贷款报价。

### 6.3 月度预算

预算工具由收入与支出计算结余和储蓄率。储蓄率 = (收入 - 支出) / 收入。当前接口要求收入大于零，零收入返回参数错误，从而避免除零；负结余如实展示。工具不把某个预算比例当作普遍适用的个人建议。

### 6.4 参数与命令

本金和收入上限为 10^12，月投入上限为 10^9，年利率允许 0 至 100%，年限必须为 1 至 50 的整数。金额最多两位小数，百分比利率最多六位小数，预算收入至少 0.01，贷款本金必须大于零。非有限数、未知字段、缺失参数与越界值通过 Pydantic 校验拒绝。

聊天窗口支持明确的工具命令，例如 `compound principal=10000 annual_rate=5 years=10 monthly_contribution=500`。系统不会从含糊的自然语言中猜测数值参数；日常用户可直接使用计算面板。内部精度为 60 位，展示值采用 ROUND_HALF_UP 保留两位小数。

## 7. 接口与数据契约

JSON 请求采用 UTF-8；接口返回实际处理模式与可展示的错误信息。`/docs` 提供不依赖外部 CDN 的本地接口说明与请求测试页，`/openapi.json` 提供 FastAPI 生成的机器可读路由和请求字段约束。当前成功响应未声明 Pydantic response_model，OpenAPI 不能据此提供完整的成功响应结构；响应字段见下表并以实际接口输出为准。

| 方法与路径 | 作用 | 主要输入或输出 |
| --- | --- | --- |
| GET /api/health | 健康与配置状态 | status、mode、model、knowledge_documents、version |
| POST /api/chat | 问答与会话写入 | message、session_id、language、engine；answer、sources、mode |
| POST /api/calculate | 执行计算 | kind 与对应数值；values、series、formula、assumptions |
| GET /api/models | 查看云端/本地引擎及训练可用状态 | models 列表 |
| GET /api/knowledge | 查看知识条目元数据 | documents 列表 |
| GET /api/sessions | 会话列表 | sessions 列表 |
| POST /api/sessions | 创建会话 | 可选 title |
| GET /api/sessions/{id} | 读取消息 | 会话与 messages |
| DELETE /api/sessions/{id} | 删除会话 | 删除结果 |
| GET /api/sessions/{id}/export | 导出 JSON | 可下载会话与引用 |

客户端不应依赖页面显示的文案来判断调用模式，应读取返回的 `mode`。无效参数返回校验错误；不存在的会话应返回明确错误，不静默使用另一个会话。

错误状态包括 422（参数或疑似密钥输入）、404（会话不存在）、403（跨源写入）、413（声明的请求长度超限）与 429（聊天请求过频）。生成服务失败通常返回成功的离线回答及 `warning`，这与 HTTP 故障是两类状态。

SQLite 中 `sessions` 保存 UUID、标题与 UTC 时间戳，`messages` 保存角色、正文、来源 JSON、模式、计算结果与警告。每个用户/助手消息对在同一事务中提交；删除会话通过外键级联删除消息。后端使用有限数量的锁序列化同会话写入和删除。历史列表最多返回最近 100 个会话。

### 7.1 DeepSeek 集成细节

请求固定发送到官方 `https://api.deepseek.com/chat/completions`，使用 Bearer 鉴权，默认模型为 `deepseek-flash`。适配器关闭 thinking 与流式输出，temperature=0.2，max_tokens=1400。HTTPX 连接操作超时为 10 秒，读取、写入和连接池操作超时默认各为 45 秒；外层另用 asyncio.timeout 对整个网络调用设置默认 45 秒的总期限，由 `DEEPSEEK_TIMEOUT` 控制。超时转为明确标识的离线回答。不跟随重定向，以避免凭据被转发到非预期地址。

系统将本次来源与最近最多 8 条历史消息加入请求；每条历史内容最多 2500 字符。当前实现未进行自动计费重试。401、402、429 分别归类为鉴权失败、余额不足和服务限流，其余异常包括网络超时、格式错误、空回答和被截断的回答。错误详情不回显第三方原始响应体或鉴权头。

对不属于已检索来源的引用标识进行替换，防止未知标识被界面当作有效来源。合法标识仍可能被模型错误引用，因此这项检查不能证明陈述与来源一致。

## 8. 配置、启动与运维

所有启动、测试和评估命令记录在项目 README。实际运行以 `requirements.txt`、`.env.example` 和 OpenAPI 为准。`.env` 保存本机配置，不能加入源代码压缩包或版本库。配置时仅填写 API Key，不把 Tracking ID 当作 Bearer Token。

默认服务应绑定本机回环地址。SQLite 和静态知识库适合单机课程演示。中间件限制本机 Host、阻止跨源写操作、提供 CSP 等安全响应头，并按来源 IP 限制每分钟 20 次聊天请求。请求声明长度超过 32 KiB 时拒绝。这些是本机演示的基础控制，不构成完整公网防护。

对公网开放之前需要额外实现用户认证、用户数据隔离、HTTPS、更健全的限流、监控、备份与恢复策略，不能把本机演示版本视为多用户生产系统。SQLite 当前不提供应用层加密。

已提交给 DeepSeek 的用户问题和有限上下文会跨越本地边界，因此不应输入身份证号、银行卡号、真实账户凭据或其他不必要的敏感资料。SQLite 会保存会话正文；删除会话不等于对磁盘、备份或服务商记录进行安全擦除。

## 9. 密钥、输入与提示注入

密钥通过服务端环境加载，前端代码和 API 响应不应包含密钥。报告、截图、错误信息及导出文件不得写出密钥。用户在聊天中提供的密钥已暴露在聊天记录中，建议轮换，并只在本地配置新值。

对知识文本与用户问题要保持信任边界：用户输入和检索片段是待分析数据，不能覆盖系统约束。系统提示应限制金融教育范围，要求标明不确定性、避免伪造行情、区分地区与不执行交易。然而提示词与过滤并非绝对防线，不能声称完整防御所有提示注入。

确定性计算路径避免通过 `eval` 执行任意表达式。输入验证拒绝无效数值和超出范围的参数。前端将内容按文本展示，以降低脚本注入风险。外部来源链接应在新窗口安全打开。

## 10. 验证方法与证据

v1 验证分为以下层次：计算与边界条件单元测试；问答、会话、导出与错误路径接口测试；固定知识检索评估；真实 DeepSeek 请求及浏览器验收。各层分别记录，不能用单一通过率概括整个产品。

自动化验证结果以 `reports/` 中的实际输出为证据。最终数值与真实 API 状态见功能报告。测试输出不是对未来每一次请求的保证：网络状态、账户余额、模型版本和第三方服务策略都可能改变。

### 10.1 一次真实生成错误及回归

初次英文真实 API 样本虽然正确给出 APY 换算公式，却将正 APY 除以 12 的误差方向写反，声称这种做法低估等效月利率。正确关系是正 APY 下直接除以 12 会高估等效月利率。审查后在知识条目与系统提示中明确该不等式，并执行真实 API 定向回归；`reports/rate_regression.json` 记录了重测的正确解释。

原始样本保留在 `reports/live_integration.json`，避免用覆盖记录制造“从未出错”的印象。初次 5/5 自动检查验证的是响应路径和期望模式，不代表五个答案全部通过事实审查。该问题说明必须将检索质量、接口正确性与答案语义质量分别评估；定向修正也不代表从此消除了所有生成错误。

浏览器语音功能依赖 SpeechRecognition 或 webkitSpeechRecognition 与 speechSynthesis。语音识别通常还需要浏览器权限，且部分实现会使用浏览器厂商的在线服务。API 不可用、权限被拒绝或没有可用声音时，应提供明确反馈，保留文字操作路径。

## 11. 已知限制与后续工作

知识库是有限的静态教育资料，不能覆盖最新产品、行情和法规。词法检索对复杂语义的泛化有限。来源检索正确不等于生成答案完全正确。当前版本不使用流式输出，模型请求较慢时用户需要等待。

系统没有真实用户研究结果，不能据开发者验收声称具有经验证的可用性提升。金融输出没有替代专业人士审核；没有接入真实交易账户，也没有对收益预测进行回测。语音仅为浏览器能力增强，不保证所有设备表现一致。

后续可在建立独立测试集和人工答案评分标准后，再比较向量与混合检索；增加逐句引用、资料版本管理、来源失效检查、隐私可控的语音方案和用户隔离。技术复杂度的增加应由评估收益支持。

## 13. v2 Avatar 与事件状态机

`web/avatar.js` 实现原创程序化金融教练，提供真实三维网格、透视相机、材质和灯光。Three.js 固定为 0.187.0，代码与 MIT 许可证位于 `web/vendor/three/`，npm 完整性校验及文件 SHA256 保存于 provenance.json。运行时不使用远程 CDN、外部人物资产或在线数字人服务。

WebGLRenderer 使用 WebGL2；在能力缺失、初始化失败或上下文丢失时显示同一角色的原生 SVG 2D 形象。用户也可主动切换二维模式。这里的 3D 指实际 WebGL 网格渲染，不是预录视频或把二维图片做 CSS 旋转。程序化角色没有人体骨骼和写实表情捕捉。

状态为 idle、listening、thinking、speaking、error。前端根据请求等待、浏览器识别 onstart/onend 与语音合成 onstart/onend/onerror 驱动状态。朗读嘴部以数学周期近似运动，没有取得音素或音频幅度，不称为精准口型同步。Avatar 自身不访问麦克风或摄像头。

模块通过 `window.FinPilotAvatar.mount(container, options)` 返回实例，支持 setState、setMode、setLanguage、setReducedMotion、getStatus 和 destroy。挂载和实际渲染模式变化可由 finpilot-avatar-status 事件检查。状态标签同时作为可访问名称，颜色不是唯一反馈。

渲染像素比上限 1.8；三维动画约以 30 帧/秒为上限，页面隐藏、角色离开视口或开启减少动画时停止连续渲染。ResizeObserver 适配容器，销毁时释放几何体、材质、纹理、WebGL 上下文和监听器。二维 CSS 动画同样尊重减少动画偏好。独立验收脚本验证真实 WebGL2、五状态、模式切换、动画停止、销毁及强制降级；合成状态测试不代表真实麦克风操作已成功。

## 14. v2 本地 LoRA 实验设计

本地引擎使用公开基座 Qwen/Qwen3-0.6B，固定 revision 为 `c1899de289a04d12100db370d81485cdf75e47ca`。模型卡采用 Apache-2.0 许可并支持 non-thinking 模板。训练使用 PEFT LoRA：冻结基座，针对 q_proj、k_proj、v_proj、o_proj 学习低秩矩阵；当前配置 r=8、alpha=16、dropout=0.05。这里采用 LoRA，不是量化基座的 QLoRA，也没有训练整个 DeepSeek 模型。

对于原权重 W，LoRA 的推理形式为 W' = W + (alpha/r)BA，其中 A 的维度为 r × d_in，B 为 d_out × r。原 W 保持冻结，优化器只更新适配器参数；这使可训练参数与输出适配器显著小于完整基座。是否改善本项目任务仍需相同条件下的实际对照，不能由参数更少直接推导准确率更高。

项目自编问题和依据官方来源整理的目标回答组成数据。18 个知识主题按组拆分为 12 个训练主题、3 个验证主题、3 个测试主题；同一主题的中英文改写不跨集合。当前数据为 144 条训练、12 条验证、12 条测试。数据清单包含文本文件哈希和来源说明，不使用真实用户会话或外部教师 API 生成答案。

训练目标是带来源、限制和金融教育提示的回答组织方式。仅助手完成部分的 token 参与损失，用户问题与提供的依据被屏蔽。随机种子 42，batch size=1，梯度累积=4，AdamW 学习率 0.0002，默认 3 轮；启用梯度检查点以控制显存。脚本拒绝静默截断目标答案。训练完成后才写入真实步数、耗时、适配器哈希与训练清单，不把安装依赖或下载权重称为微调完成。本轮真实训练已完成 3 轮、108 步，可训练参数 2,293,760（含适配器总参数的 0.383352%），训练耗时 181.51 秒，峰值已分配显存 1,912.63 MiB；详细证据及适配器哈希见功能报告。实际本地 API 中英文生成与工具路由亦已运行，分别按 local-lora / calculator 标记，记录位于 reports/local_integration.json。样例的冷/热生成约 15.06/10.71 秒，不以本地部署推导低延迟。

对照评估使用同一固定基座，在相同证据、问题与解码设置下比较加载适配器前后。记录平均逐样本的助手 token 交叉熵，以及引用出现、无未知引用、三段格式、教育提示和 EOS 停止等窄指标。测试主题虽然未进入训练，仍来自同一人工整理知识库，提问模板也与训练共享；12 条测试实际只有 6 种主题-语种上下文，双语内容还来自相同主题；目标回答大量提取给定摘要。因此不是 12 个独立金融知识任务，低损失也不证明金融推理或事实准确率提高，更不能证明胜过 DeepSeek。本轮实际对照记录平均逐样本助手交叉熵 1.441124 降至 0.004211，期望来源编号从 8/12 到 12/12，目标三段格式从 0/12 到 12/12。12 个适配器输出均逐字等于项目参考答案，说明这组 source-conditioned structured-copy 任务被稳定学到；不应称为开放金融推理提升。完整 24 个原始输出和窄指标见 reports/finetuning_evaluation.json。

主应用通过 `app/local_llm.py` 启动独立 Python 推理子进程，使用单个锁串行处理请求。模型只从预先下载的本机缓存读取，local_files_only=True、trust_remote_code=False；不因普通聊天下载新权重。模型列表的 available 是训练清单、权重哈希和 Python 路径的预检，不是完整加载或推理成功证明；缓存缺失仍会在实际调用时明确降级。本地提示采用与训练逐字一致的 app/local_prompt.LOCAL_SYSTEM，依据按 [id] snippet 给出当前语言文本，以减少训练与部署输入差异；云端仍采用独立的较长提示。本地上下文只带最近 2 条历史，每条最多 600 字符，最多 8192 输入 token；超限、超时、未正常 EOS 停止或工作进程异常会返回明确的离线知识摘录。默认本地推理期限为获得串行锁后的 60 秒，不是包含排队等待的整个 HTTP 总时限。新生成 token 最多 512 个，未遇到正常停止符时不把截断文本标为完整回答。子进程环境去掉常见密钥变量，避免把云端 Key 作为配置传入，但这不是操作系统沙箱，不能据此声称对子进程完全隔离本机文件。关闭服务会终止进程并等待，必要时强制结束。

## 15. v2 可用性与创新表述

界面增加可持久化明暗主题、可折叠助手面板、减少动画设置、实际引擎选择和来源摘要展开。有限 Markdown 使用 DOM 文本节点与允许的结构构建，原始模型 HTML 不执行；只有与返回来源匹配的编号才建立来源链接。改版目标是阅读层级、证据核查和状态反馈，没有真实用户研究时不报告虚构的效率提升百分比。

可在展示中称为“证据可见的金融学习助手”：3D 状态机解释系统活动，RAG 提供来源，确定性工具承担金额计算，LoRA 提供可复现的小模型适配实验。其创新是项目内的工程集成和验证流程，不宣称提出新的底层大模型算法。v1 的 45 项测试、48 条检索验收和 13 项浏览器流程作为基线保存于 reports/v1_baseline/；v2 的新成绩见功能报告。
